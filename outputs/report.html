How to read this report: Start with anomaly volume (Module 1), pattern strength (Module 2), diagnosis (Module 3), then Module 4’s per-machine plan. Module 6 (optional) is a separate RL demo: a policy learned in a toy simulator from three risk bands—see that section for details.

Module 1 blueprint

Input: sensor readings + threshold config

Processing: rule checks classify each row as normal or anomaly

Output: `classifications.jsonl` + alerts

Feeds into: Module 2 pattern mining and Module 3 fact extraction

Module 2 blueprint

Input: time-ordered records (+ optional Module 1 labels)

Processing: graph search (BFS/DFS/A*) to find pre-failure paths

Output: `sequences.json` + `warning_signs.json`

Feeds into: Module 3 diagnostic inference

Module 3 blueprint

Input: KB rules + Module 1/2 artifacts

Processing: inference builds ranked hypotheses and inspections

Output: `diagnosis.json` with per-equipment scores

Feeds into: Module 4 maintenance optimization

Module 4 blueprint

Input: diagnosis risks + action/cost constraints (+ optional production cap)

Processing: greedy seed, hill climbing, simulated annealing, contingency analysis

Output: `maintenance_plan.json` with actions, totals, and strategic summaries

Feeds into: operational planning; Module 6 can reuse the same action vocabulary

Module 6 blueprint

Input: the same diagnosis summary Module 4 uses, collapsed into three fleet-wide risk bands (low / mid / high), plus a small mdp.json file that describes a toy world: likely next risk level and cost after each action

Processing: the computer runs many imaginary maintenance episodes in that toy world and learns a table of “best action so far” per band (Q-learning)

Output: rl_policy.json (the table), rl_training.json (learning curve), rl_metrics.json (scores vs simple baselines)

Note: no neural nets or Module 5 classifier—just explicit rules in JSON + textbook RL for the course demo

Module 6 — Learned maintenance policy (reinforcement learning)

Module 6 runs Q-learning in a toy simulator (mdp.json) to pick a default defer, inspect, or repair for each coarse fleet risk band from diagnosis.

Reading the table: Each row is one coarse risk band. The action is the one the agent would pick in the simulator after training (defer = wait, inspect = cheaper check, repair = major work). Action names match Module 4 so you can compare vocabulary side by side.

Recent training score (average return, last training episodes): -2249.38

Returns add up simulator rewards each episode; in this project rewards are usually negative (costs). Higher numbers (closer to zero) mean better simulated performance. See rl_metrics.json next to the outputs for comparison to “always defer” and random baselines.
